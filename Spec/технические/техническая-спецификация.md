# Technical Spec: San Porfume

## 1. Назначение Документа

Этот документ переводит feature specs проекта San Porfume в технические решения для разработки.

Feature specs отвечают на вопрос, что должен видеть и делать пользователь. Technical spec отвечает на вопросы:

- какие страницы нужны;
- какие данные хранить;
- какие API нужны;
- как связаны главная страница, каталог, карточка аромата и админка;
- как обрабатывать ошибки и пустые состояния;
- что не входит в первую техническую версию.

## 2. Состав Первой Версии

В первую техническую версию входят:

- главная страница;
- блок ассортимента на главной странице;
- карточка подробностей аромата;
- кнопки связи WhatsApp и Telegram;
- простая админ-панель для управления ассортиментом;
- хранение данных ароматов;
- загрузка и отображение фото;
- пустые состояния и основные ошибки.

В первую версию не входят:

- регистрация клиентов;
- личный кабинет клиента;
- корзина;
- онлайн-оплата;
- оформление заказа на сайте;
- большой каталог с фильтрами;
- аналитика;
- отчеты;
- сложные роли и права доступа.

## 3. Страницы И Навигация

### 3.1. Пользовательская Главная Страница

Рекомендуемый маршрут:

`/`

На странице отображаются:

- главный экран с названием San Porfume;
- короткое описание магазина;
- город: Грозный;
- акцент на оригинальные парфюмы;
- блок ассортимента;
- контактные действия WhatsApp и Telegram.

Каталог не выносится в отдельную большую страницу. Для первой версии ассортимент находится на главной странице.

### 3.2. Подробности Аромата

Возможные варианты реализации:

- модальное окно поверх главной страницы;
- отдельный маршрут вида `/perfumes/[id]`.

Для первой версии рекомендуется модальное окно, потому что ассортимент небольшой, а путь пользователя короткий.

В подробностях аромата отображаются:

- фото;
- название;
- объем;
- цена;
- наличие;
- описание;
- основные аккорды;
- WhatsApp;
- Telegram;
- действие возврата к списку.

### 3.3. Админ-Панель

Рекомендуемый маршрут:

`/admin`

Админ-панель должна позволять:

- посмотреть список товаров;
- добавить товар;
- изменить товар;
- скрыть товар с сайта;
- удалить товар;
- поменять наличие;
- загрузить или заменить фото.

Для первой версии админка простая: один админ, без ролей, отчетов и аналитики.

## 4. Модель Данных

### 4.1. Таблица `perfumes`

Основная сущность проекта - аромат.

| Поле | Тип | Обязательное | Описание |
| --- | --- | --- | --- |
| `id` | string / uuid | да | Уникальный идентификатор товара |
| `name` | string | да | Название аромата |
| `photoUrl` | string / null | нет | Ссылка на фото товара |
| `volumeMl` | number | да | Объем в мл, по умолчанию 125 |
| `price` | number | да | Цена товара |
| `inStock` | boolean | да | Есть ли товар в наличии |
| `description` | text | да | Описание аромата |
| `accords` | string[] | да | Основные аккорды |
| `isVisible` | boolean | да | Показывать ли товар на сайте |
| `brand` | string / null | нет | Бренд |
| `gender` | enum / null | нет | `male`, `female`, `unisex` |
| `concentration` | enum / null | нет | `parfum`, `eau_de_parfum`, `eau_de_toilette` |
| `createdAt` | datetime | да | Дата создания |
| `updatedAt` | datetime | да | Дата последнего изменения |

### 4.2. Правила Полей

- `name` не должен быть пустым.
- `volumeMl` должен быть больше 0.
- `price` должен быть больше или равен 0.
- `description` не должен быть пустым для опубликованного товара.
- `accords` должен содержать хотя бы один аккорд для опубликованного товара.
- `photoUrl` может быть пустым, тогда показывается заглушка.
- `isVisible = false` скрывает товар с пользовательской части сайта.
- `inStock = false` не скрывает товар автоматически, а показывает статус "нет в наличии".

## 5. Хранение Фото

Фото товара должно храниться отдельно от текстовых данных товара.

Технически нужно определить:

- где хранятся изображения;
- какой максимальный размер файла;
- какие форматы разрешены;
- создается ли оптимизированная версия для сайта.

Рекомендуемые правила для первой версии:

- разрешенные форматы: `jpg`, `jpeg`, `png`, `webp`;
- максимальный размер файла: до 5 MB;
- на сайте использовать оптимизированное отображение;
- если фото отсутствует или не загрузилось, показывать заглушку;
- фото не должно ломать верстку карточки.

## 6. Backend И API

### 6.1. Публичные API

#### Получить Видимые Ароматы

`GET /api/perfumes`

Возвращает только товары, у которых `isVisible = true`.

Используется:

- главным экраном;
- каталогом;
- мобильной версией.

Пример ответа:

```json
[
  {
    "id": "uuid",
    "name": "Aroma Name",
    "photoUrl": "/images/perfumes/aroma.webp",
    "volumeMl": 125,
    "price": 12000,
    "inStock": true,
    "isVisible": true,
    "brand": "Brand",
    "gender": "unisex",
    "concentration": "eau_de_parfum"
  }
]
```

#### Получить Один Аромат

`GET /api/perfumes/:id`

Возвращает подробные данные одного видимого товара.

Если товар не найден или скрыт, API возвращает `404`.

### 6.2. Админские API

Админские API должны быть доступны только администратору.

#### Получить Все Товары Для Админа

`GET /api/admin/perfumes`

Возвращает все товары, включая скрытые.

#### Создать Товар

`POST /api/admin/perfumes`

Создает новый аромат.

#### Обновить Товар

`PATCH /api/admin/perfumes/:id`

Обновляет данные товара.

#### Удалить Товар

`DELETE /api/admin/perfumes/:id`

Удаляет товар.

Для первой версии допустимо физическое удаление, если нет заказов и истории продаж. Если позже появятся заказы, нужно перейти на мягкое удаление через `deletedAt`.

#### Загрузить Фото

`POST /api/admin/perfumes/:id/photo`

Загружает или заменяет фото товара.

## 7. Админ-Доступ

Feature specs говорят, что сложные роли не нужны, но технически нужно защитить админку.

Для первой версии достаточно:

- один админ;
- вход по паролю;
- закрытые маршруты `/admin` и `/api/admin/*`;
- хранение пароля не в коде, а в переменных окружения или в базе с хешированием;
- выход из админки.

Не допускается открытая админка без авторизации, потому что через нее можно менять цены, наличие и товары на сайте.

## 8. Связь WhatsApp И Telegram

### 8.1. Контактные Данные

Контактный номер:

`+79287352134`

Номер должен храниться в одном месте конфигурации, чтобы не дублировать его по коду.

### 8.2. WhatsApp

Ссылка должна открывать диалог с продавцом.

Если пользователь нажал из карточки товара, в сообщение подставляется название:

`Здравствуйте! Хочу узнать про парфюм [название парфюма].`

Если кнопка нажата не из конкретного товара:

`Здравствуйте! Хочу уточнить наличие парфюмов San Porfume.`

### 8.3. Telegram

В feature specs указан Telegram как канал связи, но не указан username или ссылка.

Технически нужно добавить:

- Telegram username продавца;
- или прямую ссылку на Telegram;
- или правило, что Telegram временно скрывается, пока ссылка не задана.

## 9. Состояния И Ошибки

### 9.1. Пустой Ассортимент

Если `GET /api/perfumes` вернул пустой список, показывается:

`Сейчас ассортимент обновляется. Напишите нам в WhatsApp или Telegram, чтобы уточнить наличие.`

Рядом должны быть доступны контакты.

### 9.2. Все Товары Не В Наличии

Если все видимые товары имеют `inStock = false`, сайт показывает товары со статусом "нет в наличии" и предлагает связаться с продавцом.

### 9.3. Нет Фото

Если у товара нет `photoUrl`, показывается заглушка.

### 9.4. Ошибка Загрузки Аромата

Если карточка аромата не загрузилась, показывается:

`Не удалось загрузить информацию об аромате. Попробуйте обновить страницу.`

### 9.5. Плохой Интернет

Если данные не загрузились из-за нестабильного соединения, показывается:

`Похоже, интернет работает нестабильно. Проверьте подключение и попробуйте снова.`

### 9.6. Ошибка Открытия Связи

Если WhatsApp или Telegram не открылись, показывается:

`Не удалось открыть связь с продавцом. Напишите напрямую на номер +79287352134.`

## 10. Мобильная Версия

Технические требования:

- сайт должен работать без горизонтальной прокрутки;
- карточки должны иметь стабильную ширину;
- изображения должны иметь заданное соотношение сторон;
- кнопки WhatsApp и Telegram должны быть удобны для нажатия пальцем;
- текст не должен выходить за пределы карточек и кнопок;
- карточка подробностей должна закрываться и возвращать пользователя к ассортименту;
- фото должно показывать заглушку во время загрузки или при ошибке.

## 11. Связи Между Частями Проекта

### 11.1. Админка И Каталог

Админ меняет товар в админке.

После сохранения:

- данные обновляются в базе;
- публичный API возвращает актуальные данные;
- каталог показывает новую цену, наличие, фото и название;
- скрытый товар больше не приходит в публичный список.

### 11.2. Каталог И Карточка Аромата

Каталог показывает краткие данные.

Карточка подробностей использует тот же `id`, чтобы получить или открыть полную информацию.

### 11.3. Карточка Аромата И Связь

Кнопки связи получают название выбранного аромата и формируют сообщение для продавца.

### 11.4. Ошибки И Контакты

Если данные не загрузились, сайт должен оставить пользователю способ связаться с продавцом напрямую.

## 12. Переменные Конфигурации

Нужно завести конфигурацию для:

- номера WhatsApp;
- ссылки Telegram;
- названия проекта;
- города;
- текста про оригинальность;
- пароля или учетных данных администратора;
- параметров хранения фото.

## 13. Критерии Готовности

Техническая часть считается покрытой, если:

- есть модель данных товара;
- есть публичная загрузка видимых товаров;
- скрытые товары не показываются пользователям;
- товар без фото показывает заглушку;
- изменение товара в админке отражается на сайте;
- наличие отображается в каталоге и карточке;
- WhatsApp открывается с текстом выбранного товара;
- Telegram работает или явно скрыт до настройки ссылки;
- пустой ассортимент показывает понятный текст и контакты;
- сайт удобно работает на мобильном устройстве;
- админка защищена от публичного доступа.
