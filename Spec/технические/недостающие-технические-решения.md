# Недостающие Технические Решения

Feature specs San Porfume уже описывают пользовательское поведение, но для полной технической спецификации нужно закрыть несколько решений.

## 1. Технологический Стек

Не указано:

- на чем будет сделан frontend;
- нужен ли отдельный backend;
- где будет база данных;
- где будет хостинг;
- где будут храниться фото.

Рекомендуемое решение для MVP:

- один веб-проект с frontend и backend;
- база данных для товаров;
- отдельное хранилище или папка для фото;
- простая админка внутри проекта.

## 2. Админ-Доступ

Feature spec говорит, что роли и сложные права не нужны, но не указано, как админ входит в панель.

Нужно решить:

- будет ли один пароль администратора;
- где хранится пароль;
- нужен ли выход из админки;
- какой URL у админки.

Минимальное решение:

- `/admin`;
- один админ;
- вход по паролю;
- закрыть все `/api/admin/*`.

## 3. Telegram

Номер WhatsApp указан: `+79287352134`.

Для Telegram не хватает:

- имя пользователя Telegram;
- прямой ссылки;
- решения, что делать, если Telegram еще не настроен.

Минимальное решение:

- добавить Telegram-ссылку в конфигурацию;
- если ссылки нет, не показывать кнопку Telegram или показывать сообщение с номером телефона.

## 4. Фото Товаров

Feature specs говорят, что фото можно загрузить и что нужна заглушка, но не указаны технические правила.

Нужно решить:

- разрешенные форматы;
- максимальный размер файла;
- где хранить фото;
- нужно ли удалять старое фото после замены;
- нужна ли оптимизация изображения.

Минимальное решение:

- `jpg`, `jpeg`, `png`, `webp`;
- максимум 5 MB;
- при замене фото старое можно удалить;
- если фото нет, показывать заглушку.

## 5. Удаление Товара

Feature spec разрешает удалить товар, но технически есть два варианта:

- физическое удаление из базы;
- мягкое удаление через поле `deletedAt`.

Для первой версии можно использовать физическое удаление, потому что на сайте нет заказов и истории покупок.

Если позже появятся заказы, нужно перейти на мягкое удаление.

## 6. Страница Карточки Аромата

Feature specs говорят, что пользователь открывает подробности, но не фиксируют формат.

Варианты:

- модальное окно;
- отдельная страница `/perfumes/[id]`.

Рекомендуемое решение для MVP:

- модальное окно на главной странице;
- отдельный маршрут добавить позже, если понадобится делиться ссылкой на конкретный аромат.

## 7. Обновление Данных После Админки

Feature spec требует, чтобы изменения сразу отображались на сайте.

Нужно решить:

- будет ли кеширование;
- нужно ли обновлять каталог без перезагрузки;
- как быстро пользователь видит изменения.

Минимальное решение:

- после сохранения админка обновляет данные в базе;
- публичная часть получает актуальные данные при следующей загрузке или обновлении списка;
- агрессивный кеш для товаров не использовать.

## 8. Валидация Данных

Feature specs говорят, что система подсказывает обязательные поля, но технически нужно зафиксировать правила.

Минимальные правила:

- название обязательно;
- объем больше 0;
- цена больше или равна 0;
- наличие обязательно;
- статус отображения обязателен;
- описание обязательно для видимого товара;
- основные аккорды обязательны для видимого товара;
- фото необязательно, можно использовать заглушку.

## 9. Тексты И Конфигурация

В specs есть повторяющиеся данные:

- San Porfume;
- номер телефона;
- текст про оригинальность;
- сообщения ошибок.

Технически лучше хранить их централизованно, чтобы не менять один и тот же текст в разных местах.

## 10. Проверка Готовности Перед Кодом

Перед разработкой нужно подтвердить:

- выбранный стек;
- где будет база данных;
- где будет хранение фото;
- Telegram-ссылка;
- формат карточки аромата: модалка или отдельная страница;
- способ входа в админку;
- нужна ли физическая или мягкая очистка удаленных товаров.
